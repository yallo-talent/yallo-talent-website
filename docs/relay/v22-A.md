**`mark-scale.ts`'s sizing algorithm had a real bug, not just a config gap.** Sumeet reported SAP/Microsoft/Salesforce reading as "too tiny" on the platform axis. Raising `axis.inkCap` (26→34) did nothing — because the search that solves each surface's display height was keeping the *first* reference height it found tied for best deviation, and for a set with slack that's the smallest end of a whole plateau of equally-optimal sizes, not a single optimum. Measured on the axis set: R=18 through R=30 all land on exactly 0.0000 worst deviation. Fixed the tie-break to keep the larger R — free size at identical deviation, since nothing in a tied band changes the objective by definition. Microsoft went 14px → 24px, SAP 9px → 16px, and the gate's own number *improved* (0.008 → 0.003). Verified the fix doesn't regress the other three surfaces: card tightened negligibly (0.004→0.005, still inside tolerance), rail unaffected (12.8% both ways — genuinely cap/floor-bound, no plateau to find there).
