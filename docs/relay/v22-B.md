## Decisions taken under delegated authority

1. **`url` on the Person schema points to `${SITE.url}/leadership#{slug}`, not a LinkedIn URL.** The authorised field list is `name`, `jobTitle`, `url`, `worksFor` only — no `sameAs` — so LinkedIn couldn't carry the identity-corroboration role it plays on `organisationJsonLd()`. Added `id={member.slug}` to each leadership card so the fragment is a real, resolvable address rather than an invented one. **Reversible, additive-only** — one attribute per card, no markup restructuring.
2. **The launcher watches StickyBriefCTA's DOM presence rather than re-deriving its `SHOW_AFTER_PX`/`HIDE_NEAR_END` thresholds.** A copied threshold is the exact defect class this codebase keeps finding (a second source of truth that drifts from the first), and it also let `StickyBriefCTA.tsx` go completely untouched, honouring "never move, resize or restyle" by the widest possible margin. **Reversible** — confined to `AssistantLauncher.tsx`; removing the `useSyncExternalStore` call restores the round 13 behaviour exactly.
3. **`ThemeToggle` mounted twice (header + drawer) rather than once with a responsive relocation of the same DOM node.** Two independent subscribers to the same external store (the `data-theme` attribute) rather than one node moved by CSS, because the header and drawer are genuinely different DOM subtrees (drawer is a separate `motion.div`, not a media-query variant of the header). **Reversible** — deleting either mount point removes exactly one control with no effect on the other.
4. **Retracted the header-only placement mid-session after measuring the overflow** — see Retractions. Not treated as done until re-measured at 0px overflow.
