## 5. Item 4: `check:sources`

`scripts/check-sources.mjs`, wired as `pnpm check:sources` and into **both** CI
lanes.

`src/lib/admin/article-draft.ts` into `src/lib/unsourced-figures.mjs`, a
dependency-free leaf module. The pane imports it and re-exports it; the gate
imports it directly. The matching logic is byte-for-byte what `66c67fb` shipped
and only its address changed. This is the arrangement `src/data/redirects.mjs`
already uses for the redirect table, and it exists for the same reason: two

have caught.

re-export, which is the proof the pane still sees the same rule.

**Drafts are exempt, published insights are not.** An article with no
`published` key at all counts as published, matching what the manifest and the
route layer do with it.

**THE TRIVIAL-PASS COUNT, ON THE REAL TREE: 0 published insights checked, 21
drafts exempt.** Every insight in the corpus is `published: false`, so the gate
finds nothing to fail on and could not, tonight, tell a working detector from a
broken one. That is exactly why the fixture is not optional.

**Red-proven twice, both watched:**

1. By hand: a published `.mdx` carrying `63%` and `1,400` with no `sources`
   block gave **exit 1**, naming both figures. Deleting it gave **exit 0**.
2. By the gate itself: `--selftest` writes a real fixture `.mdx` into

control's 32px. So whenever the client rail sits in the vertical band the FAB
occupies, the pause control is entirely behind it. All nine of the gate's
sample points land on the FAB and it reports SC 2.4.11.

**Why it is intermittent.** Locally the probe reaches tab stop 8 with
`scrollY: 0` and the control at `top: 1786` against an 844px viewport, so the
gate's own `if (r.top > innerHeight) return null` guard skips it before the
occlusion test runs. It only fails when the page is scrolled such that the
control is on screen AND in the FAB's band. CI's slower runner lands there; this
machine did not in five consecutive runs.

**This is a live defect on yallo.co, not a branch defect.** PR #23 is one line
of config off `main`, and round 24 changed neither surface.

**It is a keyboard AND a touch failure.** WCAG 2.2 SC 2.4.11 Focus Not Obscured
(Minimum) is the AA criterion the gate names, and the practical consequence is
worse: the FAB takes the pointer events, so at that scroll position a touch user
cannot reach the pause control either. R7 put that control there precisely so
the rail's loop would have a route for keyboard and touch users. In this band it
has neither.

**Not fixed tonight, and deliberately so.** Every candidate fix moves or
re-layers a ratified surface: the control's placement is R7's, the FAB is
canon A3 allow-listed, and R-A9 leaves that call with Sumeet. The mechanical
options are to move `.railPause` to the rail's left edge below 640px, to raise
it above the FAB, or to suppress the FAB while the rail has focus-within. The
first is the only one that also fixes touch.

*Question for Sumeet: which of the three, or another? A one-line answer unblocks
it; the measurement above is all the diagnosis it needs.*

**PR #23 is therefore left RED rather than re-run to green.** Re-running until
the probe misses it would be exactly the paper-over this section was written to
prevent.
