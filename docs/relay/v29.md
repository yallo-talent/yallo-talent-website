## 1. Shipped

### §5 — the redirect map, the cutover blocker (`bd3ee47`)

Measured before it was diagnosed, and the measurement is the finding. Game plan
§7's map existed in two states: about a third of it hand-written into
`next.config.ts`'s `redirects()`, the rest only in the plan document, with
nothing comparing the two. Asking the running server produced three defects, all
class-wide rather than one-off:

1. **Every legacy URL took two hops in its published form.** WordPress served
   everything with a trailing slash, and Next normalises the slash with its own
   308 *before* `redirects()` is consulted: `/about-us/` went to `/about-us` and
   only then to `/about`. Middleware sits after that normalisation too, so the
   only way to answer in one hop is to switch the normalisation off
   (`skipTrailingSlashRedirect`) and own it in the middleware — canonicalise
   first, look up, answer once.
2. **`permanent: true` emits 308**, where game plan §7 and round 21 §5 both
   specify 301.
3. **Ten destinations answered 404.** None of the 21 insight articles is
   published, and three case-study slugs have no file at all. Those entries were
   handing the legacy URL's authority to a dead page, which is worse than
   leaving the URL alone.

The table now lives in `src/data/redirects.mjs` and nowhere else. The middleware
answers from it and the gate walks it. Plain `.mjs` because the middleware
bundle and a `node scripts/*.mjs` gate share no build step, and a parsed second
copy is the defect the file removes.

Destinations resolve through a generated manifest of what is actually published
(`pnpm published:manifest`, checked in CI), so an unpublished article's legacy
URL reaches the hub and starts pointing at the article the day it is published.

The §7 rows that had never been implemented are now in: the overview/expertise
split across all three taxonomies, `/managed-it-coe`, `/talent-in-a-box` and its
typo variant, `/tsea-as-a-service` and its typo variant, `/white-papers`,
`/leadership-team`, `/about-us`, `/contact-us`, `/join-us`, `/join-yallo`,
`/technologies/sap`, consumer-retail, and `/home-4` — the ruled exception to
never-301-to-the-homepage, since that page *is* a draft homepage competing with
the real one.

### §2 — the research PDF becomes a designed document (`021ee91`)

The rendered pages are what found the defects, and §2.3 was right to demand
them: byte length, text fingerprint and heading count were all green on the
output Sumeet rejected. Read as images, the old document showed the navigation
bar and the "Start a brief" button on its cover, the assistant launcher floating
over the title, the last two pages given to the site footer's link columns, a
grey screen ground on every sheet, and every figure written out as prose.

`scripts/render-pdf-pages.mjs` is the instrument: it rasterises the PDF through
pdf.js so the pages can be looked at rather than counted.

Shipped: a cover with the petal signature, PetalPlate art keyed to the slug, the
source-and-date line and no body text; running furniture in the page margin
(title, `yallo.co`, page number) with the title read off the rendered `h1` so it
cannot disagree with the document; one chart per family as a dot plot, every row
measured from its own zero; a closing page carrying the brief CTA, the four-city
footprint and §2.2's colophon verbatim; chrome removed structurally rather than
by naming each piece.

Three defects came only from reading the pixels: coincident dots hid one series
entirely in *both* drawing orders (the UK mark is now an unfilled ring, so the
gold reads through it), only one of the two values was labelled, and the longest
skill label overran its gutter into the plot.

**Mechanism, per §2.3.** Unchanged in kind and it already satisfied the ruling:
a dedicated print route rendered headless by Playwright, which is already a
devDependency. Deterministic at build, fonts embedded by Chromium, charts vector
SVG, no third-party service. `check:research-pdf` fails when the print surface
and the committed PDF disagree, so a stale binary cannot ship.

### §2.4 — every control on the delivery surfaces reads as a control (`01cbff4`)

Third occurrence of this class after the assistant links. The two Sumeet named
had different causes and both were invisible to every gate: the submit asked for
`btn btn-primary` and **neither class exists anywhere in the repository**, and
the download link wore `gateStatus`, the class for the grey sentence under the
form.

Fixing those two would have left the class open, so the gate was extended first
and then asked. It found **seven more** on the same surfaces, each an anchor with
no class at all, and an eighth (`.nextLink`) carrying only layout so the arrow
glyph was doing all the work of saying "link". The rule is now scoped rather
than per-instance: `src/app/intelligence/layout.tsx` puts one class over the
family and `.surface a:not([class])` is exactly "a link nobody styled".

`check:interaction` gains rule 5 over the three delivery surfaces and the gate
form's three states, with the API stubbed at the network so the post-submit
state is reachable without a database, a mail provider or a captured lead.

### §3 — the assistant, calibrated (`7c8cb0b`)

**Labels.** The bare `/` was upstream of the corpus: `CITATION_PATTERN` required
a lowercase letter after the slash, so the root path matched nothing and was
left as a stray character in the prose. `linkLabel` is now **required** rather
than falling back to `title`, which is how all fourteen construction sites were
found — tsc named every one. The homepage's label is "the homepage".

**Length.** The flat rule is replaced by §3.2's calibration. Measured before and
after with `scripts/measure-assistant-length.mjs`, which reports rather than
judges, because a pass/fail on length would be the flat rule again in a
different file:

| set | before | after |
|---|---|---|
| pointer (round 19's five) | 42-132 words, mean 73 | 35-193 words, mean 88 |
| complex (screening, multi-market) | 113-151 words, mean 132 | 194-244 words, mean 219 |
| separation | 1.8x | 2.5x |

The distribution moved the right way at **both** ends: the two purest pointer
questions got shorter (42 to 35, 46 to 58 words) while the two complex ones grew
by about two thirds. That gap is the calibration.

### §4 — page of origin (`599aa0e`)

Implemented as ruled: pathname only, via migration `0003_transcript_origin.sql`,
panel sends `location.pathname` captured in a ref **at mount** (reading it at
send time would record wherever the visitor had navigated to since), old rows
null and labelled "before 8 August 2026", retention unchanged because origin is
a column on the transcript and dies with it.

Validation is re-run server-side rather than trusted. Measured on the wire: a
pathname is accepted (200), an omitted field is accepted (200), and an absolute
URL, a query string and a protocol-relative prefix are each rejected (422). The
panel-to-API path is verified end to end — the intercepted request body from a
panel opened on `/platforms/sap` carries `originPath: "/platforms/sap"`.

## 3b. A late instruction, taken mid-round

Sumeet reported the mega-menu hover on `/platforms/microsoft`: the label and the
support line sit hard against the gold outline. Measured — `.megaLink` carried
`padding: 7px 10px 7px 0`, so the left padding was **zero** while the right was
10px. Invisible at rest because the border is transparent, and wrong the moment
it is not. It was every item of every mega panel, not that one page: the class
IS the item.

Padding alone would have indented the labels away from the column's eyebrow and
rule, which sit on the same left edge, so the fix is `padding: 8px 10px` with
`margin-left: -10px` — the text does not move and the hover box grows outward,
symmetric with the 10px it already had on the right. Verified on the rendered
panel: 11px to the left of the label, 9px above it, border included.

## 7. Risks

- **DEPLOY ORDERING: the migration must run before or with the deploy, and the
  failure mode if it does not is silent.** Measured on 8 August against the live
  database with the new code: a chat turn returns **200 to the visitor**, the
  reply renders normally, and the insert fails with `column "origin_path" of
  relation "assistant_transcripts" does not exist`. The error is caught and
  logged rather than surfaced, deliberately — a persistence failure must never
  break a conversation mid-flow — so the visible symptom is nothing at all, and
  the cost is every transcript written between deploy and migration. `add column
  if not exists` is additive and safe to run first, so the ordering is
  migration-then-deploy with no window. **This belongs in the runbook.**
- **The redirect map's editorial correctness is not gated.** `check:redirects`
  proves the server applies the table in one 301 hop to a destination that
  resolves. It cannot prove `/about-us` is *supposed* to go to `/about`, because
  editing a row moves the expectation and the behaviour together. The gate's own
  header says so. The mitigation is review against game plan §7, and the table
  is now one readable file for exactly that.
- **`skipTrailingSlashRedirect` moves a Next built-in into our code.** The
  middleware reimplements the canonicalisation for every route, not only legacy
  ones, and it uses 308 there deliberately so the API surface keeps its request
  method. A bug in `canonicalPath` would be sitewide rather than local.
- **The PDF's chrome suppression is one CSS rule.** It is structural
  (`body > *:not(main)`) rather than a list, and `check:research-pdf` asserts
  the outcome, so a regression fails rather than ships. But a layout change that
  moved page content outside `<main>` would be hidden by it.
