## 4. §3.1's question, answered by measurement

**Does the shipped PDF contain the navigation and footer text, or does print CSS
hide them while the fingerprint still counts them?**

**The PDF carries no site chrome. This is purely the gate measuring the wrong
surface.** Measured on the print surface under print media:

| String | Painted (what the PDF can contain) | `body` textContent (what the gate hashed) | `main` textContent |
| --- | --- | --- | --- |
| "Specialisms" | no | yes | no |
| "Start a brief" | no | yes | no |
| "Skip to content" | no | yes | no |
| "Group companies" | no | yes | no |
| "All rights reserved" | no | yes | no |
| "Ask Yallo Talent" | no | yes | no |

The page removes chrome from the document with
`body > *:not(main) { display: none }` — round 21 §2, after exactly that chrome
turned up in a shipped PDF. `textContent` does not read CSS, so the fingerprint
went on counting it. **Nothing is wrong with the lead asset.**

`body` measured 18565 characters, which is exactly the manifest's stored
`textLength`, confirming the old scope. `main` measures 17815.

`textContent` is kept over `innerText` for the original layout-independence
reason and one more found here: `innerText` cannot see SVG text, which on this
page is **59 nodes and 568 characters of chart labels** that the PDF does contain
as vector text.

**Watched fail, then pass, then controlled both ways.** Against the old manifest
the rescoped gate failed (18565 against 17815); after regenerating it passed.
Then, in the browser: appending text to every non-`main` child of `body` left the
fingerprint **identical**, and appending one character inside `main` **moved
it**. The gate no longer tracks the navigation and still catches the document.

## 7. Retractions

**One, and it matters.**

**Relay v38a §4 said the `/jobs` collision meant "the CV capture surface is
unreachable in production". That was too narrow, and the true shape is the
opposite.** Measured 14 Aug 2026 with a browser user agent:
`https://yallo-talent-ohog5.ondigitalocean.app/jobs` answered **200 with this
application's built Job Seekers page**. The edge rule that puts the board at
`/jobs` belongs to the pre-cutover estate and never covered the application's own
ingress. So the generated page was publicly reachable, and at DNS cutover it
would have become the site's `/jobs`.

I also told Sumeet in chat, before making that measurement, that there was "no
risk of that page reaching visitors". That was true of `yallo.co` on the day and
false of the application's own hostname, and I corrected it in the same session
once measured. The lesson is the one this repository keeps paying for: a
measurement of one host is not a measurement of the estate.

Nothing else in an earlier relay is withdrawn. No figure was invented or changed
this round, and nothing was published about a real named person, so the R-A9
carve-out has nothing to report.
