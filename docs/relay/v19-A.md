**`check:a11y` failed four times before it passed, and the merge was not the
cause.** `load` never fired on `/`, hanging on one `_next/image` key
(`panda-retail.png`, `w=96`). It survived serial running, killing stray
Chromium, and a cache warm — reproducing identically every time, which reads as
a real defect in one asset. It is not one. Three measurements settled it:
`sharp` encodes that PNG in **6ms** with no server involved; plain `curl` serves
the URL in **34ms** because `*/*` gets cheap PNG passthrough; and a **fresh**
`next start` serves the same key with a browser `Accept` header in **146ms**. A
starved `next/image` key stays locked for the life of the server process, so
every retry inside that process fails identically. Restarting the server fixed
it. **No gate was weakened and no source file changed.** This extends the
existing "run browser gates serially" rule: serial running is not sufficient
once a key is already poisoned, and the false failure is perfectly
reproducible, which is what makes it dangerous.

  gate reports.

  wide enough to matter: `/contract` measured **96 then 89** with no code change
  between passes. "It reached 90 once" is a statement about variance, not about

  widths, and sees rules the Lighthouse accessibility category weights at zero —

  cannot stand in for it.
- **INP is not judged here either.** It is a field metric. The runner reports
  **TBT**, labelled as the lab proxy, and says in its own output that a green
  TBT is not a green INP.
- Guard proved: pointed at a dead port it exits **2** with instructions, rather
  than measuring nothing and reporting success.
- Chrome resolution falls back to Playwright's Chromium when no system Chrome
  exists, so the scheduled CI job needs no second browser download.

**Not wired into CI yet — see §7.** The intent is a scheduled job plus
