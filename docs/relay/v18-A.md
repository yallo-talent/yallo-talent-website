### 4.4 The binding cause of the Perf and LCP miss, from the trace

Ruled out by measurement, so nobody re-investigates: CLS is 0.000. `server-response-time` 10ms. Text compression on. Images already modern formats and responsive. `bootup-time` 0.3s, main-thread work 1.6s, `font-display` already `swap`, **zero third-party requests**. None of these is the problem.

What the trace does say:

- **The LCP element is a text node on all eight routes** — `heroLede`, `heroSub`, `heroTitle`, `standfirst`, `BriefForm sub`. Never an image. So LCP waits on font and CSS delivery, and image work cannot help it.
- **Critical path weight: 729 KiB across 47 requests.** Fonts **5 requests, 188 KiB**. Scripts 13 requests, 353 KiB, of which **123 KiB unused**. Render-blocking CSS **4 files, 33.6 KiB**, Lighthouse attributing 307-457ms of blocking to them. Unused CSS 13 KiB. Legacy JS 13 KiB.
- **The miss is produced by the throttling model, not by slow code.** The observed, unthrottled LCP breakdown on the same run is time-to-first-byte 18ms plus element render delay 741ms. Locally the page paints in under a second. Lighthouse then replays that dependency graph over a 1.47 Mbps link with 562ms request latency and a 4x CPU throttle, and 188 KiB of preloaded font ahead of a text LCP is roughly a second of transfer on its own.

**This matters for how the gate is read.** The same build is ~0.76s observed and ~4.2s simulated. The AGENTS.md gate does not say which it means, and that is now a decision rather than a detail — see §8.

### 4.5 What I did not fix, and why

The highest-leverage lever is the font critical path: three families (Inter, Newsreader, IBM Plex Mono), five files, 188 KiB, all preloaded, in front of a text LCP on every route. The two obvious moves are `preload: false` on the mono face, which is used only for small labels, and auditing whether every loaded weight is actually used.

I did not make either. **`next/font` is configured in `src/app/layout.tsx`, and `src/app/**` is B's territory this round; typography is also a design decision governed by canon and `DESIGN.md`, not mine to trade against performance unilaterally.** The 123 KiB of unused JavaScript is likewise bundle and page composition. Both are filed in §7 rather than done.

Nothing in my own territory was worth taking: 13 KiB of unused CSS and 13 KiB of legacy JS would not move a 90 floor when LCP is the binding metric.

## 5. The two accessibility defects, and how they were found

Both were found by measuring before diagnosing, and neither was on any register.

### 5.1 Route-scoped chrome state — the mobile drawer survived browser back

§3.1 named the `setState`-in-effect pattern on the mega panel. Measuring what the effect actually synchronised turned up **the same defect on the mobile drawer, where it is materially worse and where no effect was resetting it at all.**

Measured at 360, before the fix: open the drawer, press browser back. The new page arrives with the hamburger still `aria-expanded="true"`, 33 links from the previous panel still rendered, `body` **and** `documentElement` still `overflow: hidden`, and the header still `inert`. The reader lands on a page they cannot scroll, with a header they cannot use, showing navigation for the page they left. Browser back is the one route change that no click handler covers, which is exactly why the effect existed — and it only ever covered half the state.

Fix: one `useRouteScopedState` hook, used by both. Each value is stamped with the route it was set on, so render derives the reset. No `setState` in an effect, and no cascading render per navigation. A pending hover-intent timer that fires after a navigation now stamps the route it started on and derives closed, which is the behaviour wanted rather than a side effect to suppress. The remaining effect clears the two timers and sets no state.

Verified after: browser back gives `aria-expanded="false"`, drawer node unmounted, both overflows cleared, `inert` removed, page scrollable.

### 5.2 Escape stranded focus inside the dismissed mega panel

Found while measuring 5.1. The Escape handler's focus-restore selector still required `aria-haspopup="true"` — an attribute a previous round **deliberately removed** in favour of `aria-controls`, with a comment in the same file explaining why. The selector matched nothing, so `trigger?.focus()` was a silent no-op.

Measured at 1280: open a panel, Tab to a link inside it, press Escape. The panel dismissed and focus stayed on a link inside the dismissed panel. Keyed on `data-group`, which the trigger actually carries. Verified after: focus returns to the trigger.

### 5.3 WCAG 2.5.3 Label in Name — the header brand link, on every page

Found by the Phase 8 run, on all eight routes. Two causes, and it took a wrong first attempt to establish that:

1. The gap between "Yallo" and "Talent" in the lockup was **CSS only** — `.text` is `display: flex` with `gap: 10px`, so nothing separated the words in the DOM and `textContent` read `"YalloTalent"`.
2. `YalloFlower` is `aria-hidden` but still carried `<title>Yallo</title>`, a text node inside the link, contributing a second "Yallo".

The link's accessible name is `aria-label="Yallo Talent home"`. `"yallotalent"` is not a substring of `"yallo talent home"`, so the name did not contain the visible label.

Removing the title alone did **not** clear the audit; I measured that across a full second pass of all eight routes before adding the space. Both are needed. Verified after: `textContent` `"Yallo Talent"`, contained in the accessible name, audit score 1 with zero items, `/brief` accessibility category 100. **No visual change, checked rather than assumed** — a whitespace-only node is not a flex item, and the lockup measures exactly 137.55 x 27px before and after.

**Why six rounds missed it, which matters for C:** `label-content-name-mismatch` is an axe **experimental** rule, and `check:a11y` does not run experimental rules. The repo's gate was green and correct on its own terms the whole time. Note also that this audit carries **zero weight** in the Lighthouse accessibility category — `/brief` scored 100 while failing it — so a category score cannot be used to detect it either.

## 6. A retraction, because the artefact will catch the next session

Mid-session I measured, and was about to file, a P0: that the mobile drawer never slid into view at all, sitting at `translateX(316.797px)` fully off-screen while the page was scroll-locked, and that after closing it left 33 focusable links parked off-screen — a WCAG 2.4.3 failure.

**Both were artefacts of my own tooling and neither is a defect.** The Browser pane was hidden. Framer Motion animates on `requestAnimationFrame`, and a hidden or backgrounded pane throttles rAF, so the transform freezes wherever it happened to be and `AnimatePresence` is never told the exit finished. Re-measured with forced paints, the drawer enters fully, exits, unmounts cleanly, lifts both scroll locks, removes `inert` and returns focus to the hamburger. All correct.

The speculative fix that came out of the bad diagnosis — a `key` plus a tween exit transition — was **reverted before commit**, so motion is untouched. The tell was a `requestAnimationFrame` sampling loop that timed out with the message that the pane was hidden.

**Rule for the next session: never conclude anything about a Framer Motion animation from JavaScript sampling in a hidden preview pane.** Force paints with screenshots, or use the repo's Playwright gates, which run real rAF.

## 11. Notes for B and C

**Both:**

- **Commitlint rejects `merge:` as a type.** Use `chore(merge):`.
- The pre-commit hook runs `biome check --write --staged`, which **rewrites files after you stage them**. If it reformats anything you must `git add` those paths again or the commit records the unformatted version. Two of my commits needed a second `git add` for this.
- **Backticks in a `git commit -m` string get shell-expanded.** One of my commits died on `` `mounted` `` becoming a command. Use `-F <file>`.
- `next dev` rewrites `tsconfig.json` under a custom `NEXT_DIST_DIR`. `git checkout -- tsconfig.json` before staging, every time. It tried to enter two of my commits.

**B specifically:**

- **`/` is the site's worst performing route**: Perf 79/83, LCP 5.52s/4.73s. Its LCP element is `p.Home-module__heroLede`. If you change the hero, re-measure — you can move this either way.
