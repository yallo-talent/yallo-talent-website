### R-27.5 — the live render error (P1) · `62be7ab`

Reproduced against the exact failing row, then diagnosed, in that order.

The wire carried `"attrs":"$T"` — a React temporary reference — and the server
threw *"Cannot access level on the server. You cannot dot into a temporary client
reference"*, digest `2280395671`, inside `normaliseHeadings`, two lines into the
save. ProseMirror builds a node's `attrs` with `Object.create(null)`, and React's
server-action reply serialiser encodes only objects whose prototype is
`Object.prototype`; anything else becomes a temporary reference. `Node.toJSON`
emits `attrs` only for a node that HAS attributes, so a document of bare
paragraphs crossed cleanly and one with a single heading did not. Every imported
study opens with an H2.

It was never only headings. `image`, `chart`, `youtube`, `keyFigure`, `faq` and a
`link` mark all carry attributes, so the whole editor was one attribute away from
this on every body.

`toPlainDoc` at the two points where the document leaves ProseMirror — a JSON
round-trip, because the destination is already `JSON.stringify` into a jsonb
column, and a per-node prototype fix would be an allow-list wrong the first time
a block is added.

**Why every gate was green, and what changed.** Every fixture in the repository
was the one shape that works: `check:editor` inserts its row with the column
default, an empty doc, and types a plain sentence — a paragraph with no
attributes. `check:admin-render`'s row discovery does visit a real published
study, but it only RENDERS one, and rendering never crosses the boundary that
broke. `check:admin-render` now carries the failing shape as a fixture: a heading
with a level, present before the editor opens, saved back through the action,
asserted on the network and on the row rather than on the saved pill. **Watched
red on the pre-fix build with the exact 500, then green.**

### R-27.6 — a proper preview · `a613515`

Measured before: a 1280px frame painting 1280px into a 592px pane, 688px of
sideways scroll. The frame now keeps its true viewport width — that is what makes
the 1280 register render at 1280 — and a transform scales it into whatever the
pane has, measured by a ResizeObserver because the pane is half of a responsive
grid that collapses under 1100.

**Two boxes, and the first attempt is why.** With the transform on a full-width
stage the layout box stayed 1280 wide while painting 592, so the pane could still
be shunted sideways by anything that scrolled it. `overflow-x: clip` does not
close that: the spec makes `clip` USE `hidden` when the other axis scrolls, and
this pane scrolls vertically. So the stage takes the PAINTED size and clips on
both axes, where `clip` is real because neither axis of that box scrolls.

"Open in new tab" sits beside the size controls, on the same URL the frame loads.

Asserted across both themes and both sizes: the frame renders at the selected
register, paints inside the pane, the pane cannot be scrolled sideways, and the
previewed document does not overflow its own frame. Watched red first, reporting
the exact live defect.

### R-27.7 with R-27.2 — one visual change to one shell · `cd308cc`, `33f05cc`

`(site)` and `(admin)` are two top-level route groups, so the cockpit has its own

**The 1280 overlap, in both of its parts.** Removing the public nav was half.

R-27.7's hierarchy is three Layer 1 grounds and no new value: `--bg` the page and
the rail, `--surface` the writing canvas as a bordered card, `--surface-raised`

## 4. Delegated decisions, and reversals

1. **The cockpit bar is no longer sticky.** The rail is, above 720px. Two sticky
   boxes at `top: 0` in one scroll container overlap by construction, and the
   round file named the 1280 overlap as something to close. The rail was kept
   because round 26 ruled its state and next action must stay on screen; the bar
   was dropped because its height varies with wrapping, so no `top` offset for
   the rail is correct at every width. **Reversal:** restore `position: sticky`
   on `.bar` in `src/components/admin/Admin.module.css` and give the rail a
   measured offset the way the toolbar now has one.
2. **The 360 preview is centred rather than left-aligned.** A phone-width page
   pinned to the left of a half-empty pane reads as a broken layout.
   **Reversal:** drop `margin-inline: auto` from `.previewStage`.
3. **`Admin.module.css` and `RowTitle.tsx` moved to `src/components/admin/`.**
   They are imported from outside the route tree, and the alternative was writing
   `(admin)` into eight import paths. **Reversal:** move them back and restore the
   group-qualified aliases.
4. **The preview toggles were raised from `--fs-caption` to `--fs-body-sm`.** The
   pressed one takes `--accent-wash`, which makes it a filled control held to
   A4's 15.5px role rather than the 14px meta floor. No gate had ever opened that
   pane. **Reversal:** none recommended; this is A4 applied, not a preference.

## 5. Open items, each with the question that unblocks it

1. **R-27.3(b), the pre-deploy migration job.** Dropped from this round for time,
   not decided against, and now recorded in AGENTS.md as carried. The rule is
   written and proved but it is remembered rather than mechanical. *Unblocking
   question:* should the app spec gain a pre-deploy job that runs `db:migrate`,
   accepting that it needs the production connection string in the deploy
   environment — or does the rule stay a human step, on the grounds that a deploy
   able to migrate is a deploy able to migrate wrongly?
2. **Two apex-level infrastructure rules, for Raphy.** `yallo.co` 301s to
   `www.yallo.co`, which makes `www` the canonical host — the opposite of the
   ratified position that `yallo.co` carries the authority. And
   `talent.yallo.co` is redirected to the apex at the edge before any application
   code runs, so the `noindex` this repository sets for the placeholder never
   reaches a crawler that starts there. *Unblocking question:* are both rules
   intended, and which host should serve after cutover?
3. **The slash menu's listbox is still not a full combobox pattern.** It now
   carries `aria-activedescendant`, `aria-controls` and `aria-autocomplete` on the
   textbox, which is what `textbox` permits. A screen reader is not told a popup
   opened, because `aria-expanded` is not allowed on `textbox` and the fix is a
   `combobox` wrapper. *Unblocking question:* is a rich-text field worth wrapping
   in a combobox to gain that announcement, or is the current state the right
   ceiling?
4. **The title, subtitle and body fields suppress the focus ring** and rely on
   the caret. Accepted with rationale rather than fixed — it is the documented
   decision and is what WCAG accepts for a text field. *Unblocking question:*
   should the empty state get a visible indicator, where a caret alone on a blank
   canvas is the weakest case?
5. **`check:sources` and the CI-reader gates cannot run locally**
   (`check:ci-reader-reach` needs the read-only CI credential; `check:sources`
   needs `DATABASE_URL`, which it now has). Reported rather than skipped.

## 6. Risks

1. **The route move is the largest structural change in this round** — 89 paths.
   It is mechanical and every gate that reads an app path was repointed and
   re-run, but the failure mode of the one that was not a path fix
   (`shellOf` returning `bespoke:` for every route) was SILENT, and that is the
   shape to watch: a gate that still exits 0 while measuring something else.
2. **`--rail-h` is measured in the browser.** Before the first measurement the
   toolbar falls back to the old 52px literal for one frame. It is correct after
   the first ResizeObserver callback and there is no server-side value to use.
3. **`0008` is already applied to production.** If this branch does not merge,
   the index exists in a database whose migrations table records a file that is
   on no default branch. It is `if not exists` and drops nothing, so the cost is
   a row, not a schema.
4. **Ops can now move a lead.** The refusals around it are asserted, but the
   widening is real and it is a live capability change on a production database
   the moment this deploys.
