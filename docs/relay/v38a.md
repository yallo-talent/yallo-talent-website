## 1. Shipped

### The Jobs link opens in a new tab, from one source · `aa71910`

`jobSeekersHref` is **gone**, not annotated. In its place
`src/components/layout/nav-config.ts` exports `jobSeekersLink`, built by a small
`externalLink(label, href)` helper, whose `anchorProps` carries four things as one
object: the href, `target="_blank"`, `rel="noopener noreferrer"` and
`aria-label="Jobs, opens in a new tab"`. The aria-label is derived from the label
rather than typed, so the spoken name cannot drift from the visible one. A
consumer cannot take the address and leave the warning behind, which is the whole
point of removing the bare string.

Three consumers, each a plain `<a>` and not `next/link`, because the client router
owns `/jobs` as a real route in this app and would render that page rather than
let the browser leave:

| Surface | File | Verified |
| --- | --- | --- |
| Desktop register | `NavBar.tsx` `.jobsLink` | served HTML |
| Mobile drawer | `NavBar.tsx` drawer | opened drawer, read the live DOM |
| Footer, Company column | `Footer.tsx` `quickLinks` → `FooterColumn` | served HTML |

**A correction to the dispatch's measurement, and it matters.** The footer was
**not** a consumer of `jobSeekersHref`. Its Company column carried its own
hand-copied `{ label: "Jobs", href: "/jobs" }` literal, so the same address would
have gone on rendering in the same tab there no matter what NavBar did. The
dispatch named that failure mode in the abstract — "then the fourth consumer
regresses it" — and it was already the present tense. `FooterColumn` now branches
on `anchorProps` and the footer reads the constant.

The path stays relative. No absolute `www.yallo.co` URL anywhere, per the ruling
and `docs/status/jobs-host-hop-for-raphy.md`.

**Adjacent, same class, same territory.** The two external branches in `NavBar.tsx`
— the mega row and the drawer's generic item — each hand-copied the same
`target`/`rel` pair. Both now spread the one exported `externalAnchorAttrs`.
Neither branch renders today: no item in `primaryNav` sets `external`, so those
paths are dead and the rendered output is byte-identical. This changes nothing
now; it means the pair has one definition when something does set the flag.

**What A5 caught mid-round.** I first gave the register's mark the mega panel's
hover lift, `.jobsLink:hover .externalMark { transform }`. `pnpm check:type`
failed it: A5 forbids a hover that changes only motion. Removed rather than
padded out with a second declaration — the mark inherits the link's colour, so
the label's existing hover colour already reaches it and the non-motion cue was
always there.

**The mark's colour is measured, not chosen.** `check-rendered-contrast` scores
the `↗` as a text run and exempts nothing for `aria-hidden`, and this change is
the first time `.externalMark` has ever rendered on the estate (the mega branch
that used it is dead). The panel's `--accent` at `opacity: 0.7` would therefore
have been measured as a composite against the glass header, a ground it was never
tuned for. Both new marks take their own link's colour at full opacity instead.
Measured in the browser: register mark `rgb(23, 23, 24)` against link
`rgb(23, 23, 24)`; footer mark `rgb(229, 229, 229)` against link
`rgb(229, 229, 229)`. The mega panel keeps its gold, unchanged.

Estate-wide check of the result: every one of the 173 published pages serves
exactly two `/jobs` anchors, both `target="_blank"`. One same-tab `/jobs` anchor
survives site-wide, on `/` only, and it is outside this round's territory —
section 5, open item 2.

## 2. Decisions taken, and how reversible each is

| Decision | Reversibility |
| --- | --- |
| `jobSeekersHref` deleted rather than kept as an alias | Trivial to restore, but restoring it restores the defect: a bare string is what let the footer drift |
| `anchorProps` carries the href, so one spread is correct by construction | Cheap to split href out; it would then be possible to take the address without the warning |
| `↗` inherits its link's colour on the two new surfaces | One CSS rule, trivially reversible; reverting means re-measuring the composite against the header |
| No hover lift on the register mark | A5 decided this, not taste. Reversing needs a non-motion cue in the same rule |
| The href on the drawer anchor is restated from `anchorProps` | Local to one element. It exists because a JSX spread is opaque to biome: with an `onClick` beside it, the anchor read as a static element and biome raised three a11y errors, all false. Removing the restatement returns those three errors |
| No new gate | Per the dispatch. The single-source constant is the mechanism |

belong in a printed research document: while it is in the fingerprint, **every

asset whose body did not change.

*Unblocking question:* regenerate the PDF as part of merging this, or exclude the
site chrome from the print surface first so the fingerprint stops tracking the
navigation?

*Unblocking question:* may a follow-up round change `Close.tsx` to read
