## 2. Item 1 — the editor

Design §4 in full, at `/admin/articles/[id]` and `/admin/case-studies/[id]`,
one pane serving both.

- TipTap configured **down** to `src/lib/tiptap/schema.mjs`'s allow-list rather
  than accepted whole. StarterKit ships H1–H6; H1 is the title field on this
  site, so a body H1 would publish a second first-level heading on every
  article. A node the editor can make and the publish action refuses is a trap
  laid for the writer, so the two sets are one set.
- The **seven Yallo blocks**, each with an in-place editing view.
- **Slash command**, opening only at the start of a line. `startOfLine: true`
  is deliberate: "S/4HANA" is written on this site constantly and a menu that
  opened mid-word would fight the estate's most common product name.
- **Selection toolbar** with a real link field rather than `prompt()`.
- **Autosave** on a 1.5s debounce, with a permanently visible `aria-live`
  saved state and a beforeunload guard.
- **Revision history** with per-revision preview and restore. A restore is
  itself recorded as a revision, so it is undoable by restoring again.
- **Side-by-side preview** in the real template, both themes, 360 and 1280.
- **Full-screen** mode, leaving on Escape.
- **Computed** word count and reading time, never asserted.

### 2.1 The seven blocks were a hole, not a deferral

`schema.mjs` ALLOWED all seven block types, so `disallowedNodes` accepted a body
carrying one — and `TiptapBody` returned `null` for every one of them. A
published page would have had a silent gap with no refusal anywhere. Round 25's
comment said they were "handled with the editor that produces them"; in fact
nothing refused them in the meantime. The renderer now draws all seven.

The key figure and the chart **render nothing without their source**, so a draft
preview cannot show an author a finished callout that publish rule 1 will then
refuse.

### 2.2 The preview is the real template

`/admin/preview/[type]/[id]` imports the same `TiptapBody` and the same
`EditorialLayout.module.css` the published article uses. It is not the whole
public page: the hero, sources aside and brief CTA are chrome the writer is not
editing, and at 360 in a split pane they push the body two screens down.

It sits under `/admin` and checks the **pane** role, not merely a session — an
`ops` account reaches briefs and no content, and a preview that only checked for
sign-in would be the one hole in canon A4's matrix.

## 3. Four defects found by measuring, not by looking

1. **`.prose h2` read `--fs-section-h`, which is defined nowhere on the estate.**
   An undefined custom property makes the declaration invalid at computed-value
   time, and `font-size` then resolves to *inherit* rather than falling back to
   the global `h2` rule. Every section heading in a published article would have
   rendered at body size. It was latent only because **no article is published
   yet** — it was waiting for the first one. Now `--fs-title`.
2. **The cockpit's row button read `--text-1`,** which is not on the
   `--text` / `--text-2` / `--text-3` ladder. The site's publish button had no
   colour of its own, and its hover `border-color` resolved to `initial`, so the
   hover changed nothing.
3. **Taxonomy checkboxes were 16×16,** the browser default, under SC 2.5.8's
   24px floor — reported 21 times by the cockpit render gate at 360. Now 24px.
4. **A colliding duplicate class** in the new editor stylesheet, caught by
   `check:type`: `.blockAdd` declared twice with conflicting padding, where in a
   CSS module the later block silently wins.

(1) and (2) were found by a gate written in this round; (3) and (4) by gates
that already existed.

## 5. RETRACTIONS

**One.**

In §1 of this document's first draft I was about to report the pre/post prose
comparison as proof that the flip changed nothing, **without** having
established that the after-capture was not a Cloudflare cache hit of the
pre-merge page. A byte-identical result from a cached copy proves nothing at
all, and I had not checked. The two facts now recorded in §1.1 — zero `.mdx`
files on `main`, and `x-nextjs-cache: MISS` on the measured response — were
gathered **after** I noticed the gap, not before. The conclusion survived; the
reasoning that would have supported it did not exist when I first reached it.

Also worth stating plainly, though it is a process failure rather than a false
claim: **twice** I captured a gate's exit code through a pipe
(`cmd | tail; echo $?`), which reports the exit code of `tail`. The first time
it made a failing CI run look like it had passed. Every exit code quoted in §7
was re-measured without a pipe.

## 9. Risks

1. **`ci_reader` can read `users`, `submissions` and `assistant_transcripts`.**
   That is R-25b.1 as written, and D25b-2 explains why the narrower grant was
   reverted. The property the ruling asked for holds — the role writes nothing,
   and cannot mint itself an account, which `check:ci-reader-reach` asserts
   separately because that is the larger prize.
2. **Autosave and the fields form are two writers of one row.** They are split
   deliberately — the editor owns `body`, the form owns everything else — so
   neither can revert the other. A third writer added later without that
   discipline would break it.
3. **The editor is untested against a body that a human has actually written.**
   Every assertion used a fixture. The nine imported studies open in it and were
   not edited, by rule.
4. **`check:editor` runs in the same CI step as `check:admin-render`**, sharing
   one server. If that step's server ever fails to start, two gates go red for
   one reason.
5. **The preview iframe reloads on every autosave.** On a long article that is a
   full server render every 1.5 seconds of typing while the pane is open.
   Nothing measured it; it is a plausible cost, not an observed one.
