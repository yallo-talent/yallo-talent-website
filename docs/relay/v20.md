### 3. The one recommendation, costed as far as it can honestly be costed

**Split Newsreader italic into its own, smaller, dedicated instance — a
second `next/font/google` call at `weight: ["600"], style: ["italic"]`
rather than the current combined `weight: ["400","500","600"]` covering both
styles in one variable file.**

R11A's audit found italic is rendered at weight 600 only, 3 nodes, 2 routes,
never at 400 or 500. The current file is a variable font spanning the full
400–600 range for both styles, at 63.0 KiB — a third of the entire preload
budget for two words on two pages. A dedicated static instance at one weight
would be materially smaller, and — because it would stay **preloaded** —
it sidesteps §5.3's boundary entirely: no flash of fallback italic, no
design decision needed, just less weight for the same rendered result.

**Cost not measured in milliseconds, and that is deliberate rather than an
omission.** Building it means a second font declaration, a CSS rule routing
`font-style: italic` to the new variable specifically wherever it's used,
and a rebuild — which is new lever construction, and §5.5 is explicit that
this round applies levers already identified, not invents a fourth idea.
The only honestly measured figure available is the 63.0 KiB the current
file costs; the KiB the new one would cost, and the LCP milliseconds that
would buy, both require building it first. Named for a follow-up round, not
built in this one.
