## 12. The three gates that went red on an absent server

`check:reflow`, `check:motion` and `check:yallo-case` returned 1 in one batch.
**The cause was ECONNREFUSED, not a defect**: the foreground command that owned
the server was SIGTERMed at a ten-minute timeout and took `next start` with it,
and the gates then ran against nothing. Captured before any re-run, per standing
practice, and re-run against a detached server, where all three returned **0**:
`check:reflow` across 194 routes at 320 and 360 in both themes, `check:motion`,
and `check:yallo-case` across 194 pages with 238 internal links all resolving —
which is also what proves the renamed `/insights/capabilities/*` routes resolve.

This is the "check which server is on the port" lesson arriving a third time,
and the fix is procedural: long browser gates run detached, never in a
foreground shell that can be killed under them.

## 12a. Two defects the full suite found that no single spec did

Running every spec together, rather than the ones I had just written, found two
things worth recording because both are the same shape: **a change made in one
place that a second place had to be told about.**

1. **`e2e/roles.spec.ts` carries the role matrix BY HAND**, deliberately, so

   Adding the `media` pane without updating it turned three assertions red,

   protect, and it is exactly what that file is for. Fixed; 54 assertions pass.

2. **`HeroAtmosphere` emitted duplicate React keys.** Its four petals are placed
   off a coarse grid from the page seed, and two of them CAN land on the same x,
   y and size — `/insights` does, which React reported as two children with the
   key `570-300-530`. A duplicate key is not cosmetic: React may duplicate or
   omit one of the pair. Latent before this round and reached seven more
   surfaces because of it. The index is the identity now: four petals, fixed
   order.

Neither appeared in any gate I ran per-item. Both appeared the first time the
whole suite ran in one process, which is the argument for running it that way
before opening a pull request rather than after.
